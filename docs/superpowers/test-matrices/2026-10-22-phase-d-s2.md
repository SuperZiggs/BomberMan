## Requirements-derived public acceptance seams

CLI remains `run_phase_d_s2.py` with the frozen packet's flags. Small programmatic seams below may be re-exported from that module; they do not prescribe production module layout or internal algorithms. They allow synthetic mathematical boundary tests and cancellation/fault injection without consuming full experimental seeds. Fixture data and fake evaluators live in tests, not in production.

* `config_for(smoke=False)` returns the registration `config` object.
* `canonical_digest(value, digest_key=None)` computes the packet's canonical digest.
* `build_train_schedule(arm, *, snapshots=(), recent_cursor=0, start_episode=1, episodes=2000, smoke=False)` returns `{'episodes': rows, 'recent_cursor': int}`. Rows expose `episode, block, slot, board_seed, learner_corner, opponent_type, opponent_id, opponent_sha256, recent_fallback`. `opponent_type` is `RB|fixed|recent`; fixed IDs are G/F/S/S2. Snapshots use the public checkpoint descriptor plus `arm='pool'|'control'`; only `episode < block_start_episode` is available. `episodes` is the requested count (not final episode). Smoke uses the first two paired slots of its separate namespace and creates snapshots every two episodes. Splitting at a block boundary with the returned cursor must preserve the schedule.
* `select_candidates(candidates)` accepts `{'S2': candidate, 'control': [candidate...], 'pool': [candidate...]}`. A candidate is a public checkpoint descriptor with `metrics` mapping G/F/S/S2/RB to aggregate rate dictionaries (`win_rate, active_win_rate, draw_rate, suicide_rate`, percentages). Returns `models` descriptors, `validation_summary`, and `open_test`. Episode 0 is the shared S2 candidate and is always considered even if omitted from arm lists.
* `build_test_manifest(registration, models, snapshots)` returns task descriptors as defined by the packet; identical learner SHA is evaluated once, with aliases retained by selection/report. Snapshots use the descriptor above. Tests examine semantic coverage and identity, not task ordering or private filename conventions.
* `paired_macro_comparison(left_rows, right_rows, metric, opponents=('G','F','S','S2'))` returns `difference_pp, ci95_pp, board_pairs`; rows are the packet's raw records. Two corners per opponent per board are mandatory. Defaults are 10,000 samples and seed 20261014. Supplying one opponent gives its separate paired CI.
* `decide_gates(comparisons, pool_matchups, baseline_rb, snapshot_ids)` returns `pilot_gate` and `phase_d_gate`, each with `pass` and `status`. `comparisons` has `pool_minus_S2: {'macro_cnn': metric comparisons, 'RB': metric comparisons}` and `pool_minus_control: {'macro_cnn': metric comparisons}`; each metric comparison is `difference_pp, ci95_pp`. `pool_matchups` maps opponent IDs to summaries with `games, win_rate`; `baseline_rb` is S2's same-run RB summary. Missing comparisons or matchups cannot pass.
* `validate_task_payload(task, payload)` validates without mutation and raises `ValueError` for a mismatching or invalid board result; returns normally for valid data.
* `load_registered_model(checkpoint, model_id, device='cpu')` returns the actual `ActorCriticNet` in evaluation mode, strictly 9×9/13-channel. Only model ID B may expand 12 to 13 channels with zero weights and identical logits; other shape changes must raise `ValueError` or `RuntimeError`.
* `train_arm(output, arm, *, resume=False, stop_event=None, on_episode=None, on_step=None, commit_hook=None)` is the actual normal programmatic training stage. Existing callback shapes are retained. `commit_hook(event, episode)` may inject `before_state_commit` or `after_state_commit` failures. It must not be a fake training implementation. `read_training_state(output, arm)` exposes committed state for evidence with keys `episode, model, optimizer, scheduler, rng, schedule_state, metrics, snapshots, initial_sha256, initial_optimizer_steps, opponent_audit`. Audit entries contain `id, before_sha256, after_sha256, eval_mode, gradient_count`; state fields may contain tensors. Paths/actual serialization are implementation-owned.
* `evaluate_stage(output, stage, *, resume=False, evaluator=None, commit_hook=None)` is the actual validation/test stage and ledger. An optional evaluator receives a public task descriptor and returns its public payload; tests inject deterministic outcomes and interruption only. Stage ordering/provenance/manifest/ledger/open-marker/selection checks are never replaced. `commit_hook(event, task_id)` can inject `before_task_commit` / `after_task_commit` failures.

For writer contention, tests acquire the existing `training_state.run_lock(output)` API and invoke the real stage; if D-S2 uses a separate lock, its normal lock context must be exposed as `writer_lock(output)` by the runner instead.

## Isolation and concrete limits

Tests copy the five existing immutable checkpoint files and S2 selection/test-open evidence into a temporary input root. All new registration, registry, snapshots, task shards and packages are under temporary directories. No inference on historical held-out seeds is run. Pure full schedules/manifests and gate fixtures cover full-run rules; the runnable journey is CPU smoke. A full 4,000-episode scientific pilot is deliberately not an acceptance test, so throughput/long GPU execution and the scientific result remain unproved by this suite. CUDA continuation runs only with `D_S2_ACCEPTANCE_CUDA=1` and available CUDA; this explicit opt-in avoids consuming GPU work by default. No claim of scientific PASS is inferred from passing tests.

RED counts, final SHA-256 values and exact executed commands will be appended after authoring and running the suite.

They are regression coverage, not claimed as missing-behavior RED. The final complete collection has **62 tests**, including the explicitly opt-in CUDA test. The first protocol/training/evaluation slices and every new ledger/journey behavior have recorded valid missing-behavior RED; setup/syntax/dependency problems are excluded.

Before the final runfile freeze, a first CMD invocation used technically invalid subprocess quoting; it was corrected to a temporary `.cmd` fixture and rerun. The corrected CMD path reaches the real runner and fails only because validation is not yet implemented. An initial assertion equating `spec_sha256` specifically to the requirements-packet filename was removed before freeze: the packet requires a registered spec hash but does not prescribe that source filename. Likewise the concurrent reservation test uses full mode because repeated smoke namespace ownership is not unambiguously prescribed. These are independent-author corrections before handoff, not implementation-driven weakening of frozen tests.
