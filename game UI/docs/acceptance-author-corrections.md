# Independent author corrections

These corrections were made without reading new production code, its design or its progress ledger. They correct test assumptions against `requirements.md`; implementation failures did not prompt them.

1. Python reward replay and snapshot flame/pickup coverage were strengthened immediately after the initial RED run. Original frame test checked dataclasses/copies but did not explicitly reject missing active flame/pickup data. Original replay checked only finite displayed rewards. Added nonempty active collections and equality with actual per-step rewards or cumulative sums.
2. The original training artifact assertion required `*.jsonl` metric persistence with exactly two raw rows. The frozen public contract specifies actual episode callback data in the HTTP `metrics` field, but does not mandate a log extension or full history. The test now inspects that public field recursively for actual reward/loss/win/active_win callback values; weights still must be real torch tensors and remain under UI runs. Original stop check used only `output.glob('*.pt')`; now `rglob` permits a valid nested output layout.
3. Browser original settings test required persistence across page reload. The frozen requirements require working settings, not storage persistence. It now verifies the setting survives closing/reopening the settings panel in the same app session.
4. Browser original numeric slot assertion required labels A1-A4. The requirements permit either zero or one based numbering, so it now accepts complete four-slot sequences A0-A3 or A1-A4 (and equivalent P/#/Robot/Tác tử prefixes).
5. Browser original C/D selector assertion inspected enabled options even when the entire selector was disabled at value 2. A disabled selector with other dormant options correctly prevents unsupported counts. Both valid UI implementations are accepted.
6. Browser original training test demanded simultaneous visible pause and resume buttons. A single toggling control is valid; the assertion now accepts either pause/resume state plus the required stop-and-save control. HTTP tests separately exercise both actions.
7. Browser error scenario originally asserted an error after opening the menu, implicitly requiring eager catalog loading, and accepted the generic word checkpoint. Catalog loading may occur on setup. The test opens play setup and requires actual error wording after the injected catalog failure.

No assertion about authoritative game state, transport safety, job limits, real checkpoint tensors or required UI functionality was removed.

8. Browser tracing now defaults to `off`; set `BOMBERMAN_TRACE=1` to opt into `retain-on-failure`. The parent reported the same two regression tests passing 2/2 with tracing disabled (`artifacts/review-browser-no-trace.log`), while retained tracing caused software WebGL canvas interaction and teardown to exceed the unchanged 45-second limit (`artifacts/review-browser-green.log`); standalone Chrome also worked. This adjusts diagnostic recording for the local Chrome/software WebGL environment. Assertions, screenshots and all timeouts remain unchanged. Evidence paths and results here are parent-reported; the independent author did not inspect production source.
